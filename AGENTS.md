# rust-native-ui

A small native interface toolkit in Rust, owned end to end and grown piece by piece as applications need it. Its first user is the world preview (the `world-preview` repository), then the Outpost Tools launcher. Windows first, written so that another system only replaces one crate.

## Rules that hold everywhere

- No third-party crate, except Microsoft's `windows` (bindings to the system's own API), and only inside `nui-win32`. When a need is already solved elsewhere (Taffy, microui, egui, Clay), read how they did it and write our own reduced version; if code is ever copied, keep its licence notice next to it.
- Only `nui-win32` names Windows. Every other crate speaks to the system through the traits of `nui-base`, so a Linux backend is one sibling crate.
- Simple over fine-grained: build the subset the applications use, not the general case.
- Every visible step can be checked by an offscreen picture (`--shot`), the same frame the window shows.
- Everything observed at runtime goes through the hub in `nui_base::log`.
- Repository content is English. Conversations with the maintainer are French. Comments say why, not what.
- Private: no remote is published from here.

## Where things live

- `crates/nui-base`: geometry, colours, matrices, the orbit camera, draw lists, the `Gfx` and `App` traits, the `Launcher` trait (start a child process without a window, stop it with its whole tree, show a folder), the polyline command and the shape command (a path with the winding rule), the system's scheme event, the input method's events (`Ime`) and the caret spot (`App::ime_spot`), the window's state, the hit, cursor and window-request contracts of a window with its own frame, the log hub. No OS code, no dependency.
- `crates/nui-png`: the PNG writer (deflate with fixed Huffman codes) and a reader for the files it writes, for picture tests.
- `crates/nui-win32`: the Windows backend: Win32 window, Direct3D 11 for meshes, Direct2D and DirectWrite for the interface, offscreen rendering, the system's light or dark setting and its change (`system_dark`, `WM_SETTINGCHANGE`), the input method (IMM32: the composition as `Event::Ime`, the candidate window at the caret, off outside text fields), the own frame (`run_with` and `Frame`: hit test, sizing edges, minimum size, cursors, the wake timer, occlusion), and the window's three optional keepsakes in `Frame` (`icon`: an RGBA square for the taskbar; `place`: a file where the place and size are kept at close and restored at start if a screen still shows them, its text and checks in `place.rs`; `hwnd_file`: the window's handle as a decimal while it exists), and the system launcher (`SystemLauncher`: `CREATE_NO_WINDOW`, `taskkill /T /F`, Explorer, with `std::process` only). The system's reduced-motion setting (`reduced_motion`, "Animation effects" off, read once by the app).
- `crates/nui-layout`: pure layout: flex (build step 7), the reduced grid, absolute boxes against their parent and the layout side of overflow (build step 8), tree, measure callbacks, a debug dump. No OS code.
- `crates/nui-ui`: the immediate-mode interface: ids, pointer input, the page's dark and light themes, label, button, toggle, fold, tabs, the text field and number field, the ellipsis text, the vertical scroll area with the kit's own scrollbar (a 1 px track, a 3 px thumb, a chevron arrow at each end that has content beyond it, in the theme's line, muted and text colours; shown only on overflow, in its own 11 px gutter), and the list row (also as a round mark), legend head, part head, pick links, the hover area, the icon parser, the window buttons and the grips of `chrome.rs`, the cursor shapes and the tooltips, the composition in the text field and the wide cells, and the history trend row with its plotted lines (editing model in `edit.rs`, one focused field, keys and clipboard through `nui-base`); hit tests use the last frame's rects. Depends on `nui-base` and `nui-layout` only. And, for the launcher's Home (step 21): the select with its menu (`select_menu`, painted last, outside every clip) and the same menu hung from a strip tab (`tab_menu`, with `MenuRow`s that can be disabled), the tool button with its name (`tool_button`), the launcher's icon looks (`IconLook::Square`, `Filled`, `Bare`, joined squares), the hover box, disabled text and number fields (`FieldOpts`, `number_with`), the underlined button, the toggle's own measures (`toggle_with`), and the page's ease and its 220 ms slide (`anim.rs`, `Slide`).
- `demos/shell-boxes`: the world preview's page shell laid out at 1400, 1200 and 1000 px and drawn as named boxes and the gallery of the page's grid rows and absolute boxes (`cargo test -p shell-boxes` writes `target/tmp/shell_<width>.png` and `target/tmp/gallery.png`).
- `demos/preview`: the world preview's window: the shell (step 13: bar, three columns, the real settings sections and static values) and, with `--data DIR`, the 2D map of an out folder in the stage (step 14: the five views, pan, zoom, grid, cross, ticks, structure marks, probe), in a window or as a picture, and the 3D view inside the stage (step 15: `scene.rs`, shared with `demos/relief`; left-drag turns, the wheel zooms, `--camera`), and the Section view (step 16: `section.rs` the model and the ore play, `cut.rs` the look, the sheet, the strip and the probe; wheel, drag, strip, "Another cut", the ORES list; `--cut`, `--ore`, `--cut-look`) (`cargo test -p preview` writes `target/tmp/preview_<width>.png`, `map_*.png`, `relief3d_*.png`, `section_*.png`; `docs/shots/preview-*.png`, `map-*.png`, `stage-3d-*.png` and `section-*.png` are the pictures). `tools/page_paint.mjs` and `tools/page_section.mjs` are the reference runs of the page's own `paint()` and section code in Node, which `tests/page_paint.rs` and `tests/page_section.rs` compare byte for byte. And data and runs (step 17: `run.rs`; reads `--data`, default `C:\Games\preview\out`, with its `run.json`; Generate runs the script given by `--generator`, with `--pack`, following its `progress.json`, with a stop, a queued re-run, a learned pace and the busy veil; Export writes the 2D pictures and the section sheet; tested against `tools/stub_run.ps1`, never against the real `preview.ps1` yet; everything it writes goes under `--runs`, which must lie inside `target/tmp`, and `--data` is never written) (`cargo test -p preview` also writes `target/tmp/run_40.png` and `export_done.png`; `docs/shots/run-progress.png` and `export-done.png` are the pictures). And the right column (step 18: `figures.rs` the page's `measure` and the figure cells, `history.rs` the history and its trend lines, kept in `<runs>/history.json` and `before.json`; the list follows the view; the theme follows the system's light or dark setting, `--theme dark|light|system`; `tools/page_figures.mjs` is the reference run of the page's figures, lists and history in Node, which `tests/page_figures.rs` compares bit for bit) (`cargo test -p preview` also writes `target/tmp/figures_*.png`, `history_1400.png`, `structures_list.png` and `scheme_switched.png`; `docs/shots/figures-*.png`, `history.png` and `structures-list.png` are the pictures). And the launcher's bar and the fixed panels (step 19: `bar.rs` the bar on the window's own frame, drawn as the launcher draws it, with its tool switch between Home and the preview and its icons after Pixelarticons (MIT, notice in `demos/preview/THIRD-PARTY.md`); the bar floats, with no line under it, and the content starts 10 px under it (`CONTENT_TOP`, step 19.5); the side panels are fluid (`panels.rs`: minimum 220, natural width from the widest row up to 330, map minimum 238, gaps 28 and 16, all set in one place; the stacking width, the minimum window and the bar's centred threshold derived), the centre is the column they leave with a square of side `min(column, H - 136)`, a grip in each gap drags a panel (double click resets), below 790 px the panels stack under the stage, and the bar's two buttons open and close them; titles as tooltips, cursor shapes, a wake timer instead of a busy loop, a hidden window that still follows its run, `export.json` beside the pictures, and a preview folder that cannot be read shown as the page's note instead of a closed window) (`cargo test -p preview` also writes `target/tmp/responsive_*.png`, `bar_*.png`, `tooltip.png` and `error_*.png`; `docs/shots/bar-*.png`, `responsive-*.png`, `tooltip.png` and `error-*.png` are the pictures). The preview is native as of step 19; its Home pane is a placeholder. And the host's Home and the bar's extras (step 21): `home.rs` is the trait a host fills to give the Home pane (`PreviewApp::with_home`, `picture_with_home`), the bar shows the account (`#account`) and slides the preview tool's views open and shut in 220 ms (`reduce_motion` makes it jump), the two tools carry their names beside their icons (Home, Preview), and when the window lacks room the bar gives up, from widths measured in `overflow.rs` and not from breakpoints, the account, then the greyed views (into a "More" tab at the end of the views, a `tab_menu` list), then the word MINECRAFT if that buys room, then the other views from the strip's end; the pressed view stays and the tools' names never go, and a run's folders can be named one by one (`Runs::server_dir`, `out_dir`, `exports_dir`). The native launcher itself lives in the pack's repository, `launcher/native`, and depends on these crates and on `demos/preview` by path.
- `demos/relief`: the preview's 3D scene alone in a window (or as a picture) with a facts plate; it reads the `out` folder through the `preview` crate.
- `demos/widgets`: the widgets in the page's looks: a live window, `--shot`, and `cargo test -p widgets` writing `target/tmp/widgets_dark.png` and `widgets_light.png`, plus the input method sheet (the same test run writes `target/tmp/ime_<theme>.png`), and the controls sheet (folds, strip, choice, details, number fields): the same test run writes `target/tmp/controls_<theme>.png`, and `--controls` opens it live; the fields sheet (text and number fields driven by scripted events): the same test run writes `target/tmp/fields_<theme>.png`, and `--fields` opens it live; the lists sheet (biome list with scrollbar, a narrower list with absent rows, trend rows): the same test run writes `target/tmp/lists_<theme>.png`, and `--lists` opens it live. The launcher controls sheet (step 21: icon buttons, select and its menu, disabled and left-aligned fields, toggle, hover row, underlined word): the same test run writes `target/tmp/launcher_controls_<theme>.png`, and `--launcher` opens it live.
- `GLOSSARY.md`: the project's words (bar, tool, view, strip, panel, stage, cut, probe, run…), confirmed with the maintainer; name things this way.
- `docs/design.md`: the design dossier (module tree, reduced flex/grid, text field, build plan, risks).
