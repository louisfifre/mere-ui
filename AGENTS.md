# mere-ui

A small native interface toolkit in Rust, owned end to end and grown piece by piece as applications need it. Its applications, the world preview's window and the Outpost Tools launcher, live in the `outpost-tools` repository. Windows first, written so that another system only replaces one crate.

`mere` is the family of the maintainer's base libraries (nothing more than what is needed, nothing borrowed): this kit is `mere-ui`, every crate of it is `mere-<part>`, and a later sibling library would be `mere-net`. It was `rust-native-ui` (crates `nui-*`) until 0.11.0.

## Rules that hold everywhere

- No third-party crate, except Microsoft's `windows` (bindings to the system's own API), and only inside `mere-win32`. When a need is already solved elsewhere (Taffy, microui, egui, Clay), read how they did it and write our own reduced version; if code is ever copied, keep its licence notice next to it.
- Only `mere-win32` names Windows. Every other crate speaks to the system through the traits of `mere-base`, so a Linux backend is one sibling crate.
- Simple over fine-grained: build the subset the applications use, not the general case.
- Every visible step can be checked by an offscreen picture (`--shot`), the same frame the window shows.
- Everything observed at runtime goes through the hub in `mere_base::log`.
- Repository content is English. Conversations with the maintainer are French. Comments say why, not what.
- Licensed GPL-3.0-only (`LICENSE`, and `license` in every crate's `Cargo.toml`). Written to be public; publishing it stays the maintainer's decision.
- No path of a machine in the repository: a folder a test or a demo needs comes from an argument or an environment variable, and a test without it says "skipped".

## Where things live

- `crates/mere-base`: geometry, colours, matrices, the orbit camera, draw lists, the `Gfx` and `App` traits, the `Launcher` trait (start a child process without a window, stop it with its whole tree, show a folder, ask the person for one), the polyline command and the shape command (a path with the winding rule), the system's scheme event, the input method's events (`Ime`) and the caret spot (`App::ime_spot`), the window's state, the hit, cursor and window-request contracts of a window with its own frame, the log hub. No OS code, no dependency.
- `crates/mere-png`: the PNG writer (deflate with fixed Huffman codes) and a reader for the files it writes, for picture tests.
- `crates/mere-win32`: the Windows backend: Win32 window, Direct3D 11 for meshes, Direct2D and DirectWrite for the interface, offscreen rendering, the system's light or dark setting and its change (`system_dark`, `WM_SETTINGCHANGE`), the input method (IMM32: the composition as `Event::Ime`, the candidate window at the caret, off outside text fields), the own frame (`run_with` and `Frame`: hit test, sizing edges, minimum size, cursors, the wake timer, occlusion), and the window's three optional keepsakes in `Frame` (`icon`: an RGBA square for the taskbar; `place`: a file where the place and size are kept at close and restored at start if a screen still shows them, its text and checks in `place.rs`; `hwnd_file`: the window's handle as a decimal while it exists), and the system launcher (`SystemLauncher`: `CREATE_NO_WINDOW`, `taskkill /T /F`, Explorer, with `std::process` only; the folder dialog is the shell's own, `IFileOpenDialog`, modal over the window). The system's reduced-motion setting (`reduced_motion`, "Animation effects" off, read once by the app).
- `crates/mere-layout`: pure layout: flex (build step 7), the reduced grid, absolute boxes against their parent and the layout side of overflow (build step 8), tree, measure callbacks, a debug dump. No OS code.
- `crates/mere-ui`: the immediate-mode interface: ids, pointer input, the design system's values in `tokens.rs` (the palette, the spacing scale and its roles, sizes on a 4 px grid, four fades; a widget takes every colour and measure from there, a padding counting the 1 px frame), the dark and light themes as roles pointing to the palette, label, button, toggle, fold, tabs, the text field and number field, the ellipsis text, the vertical scroll area with the kit's own scrollbar (a 1 px track, a 3 px thumb centred on it, a chevron arrow at each end that has content beyond it, in the theme's line, muted and text colours; shown only on overflow, in its own 12 px gutter), and the list row (also as a round mark), legend head, part head, pick links, the hover area, the icon parser, the window buttons and the grips of `chrome.rs`, the cursor shapes and the tooltips, the composition in the text field and the wide cells, and the history trend row with its plotted lines (editing model in `edit.rs`, one focused field, keys and clipboard through `mere-base`); hit tests use the last frame's rects. Depends on `mere-base` and `mere-layout` only. And, for the launcher's Home (step 21): the select with its menu (`select_menu`, painted last, outside every clip) and the same menu hung from a strip tab (`tab_menu`, with `MenuRow`s that can be disabled), the tool button with its name (`tool_button`), the launcher's icon looks (`IconLook::Square`, `Filled`, `Bare`, joined squares), the hover box, disabled text and number fields (`FieldOpts`, `number_with`), the underlined button, the toggle's own measures (`toggle_with`), and the page's ease and its 220 ms slide (`anim.rs`, `Slide`). And the overlay (`Ui::overlay`): a framed box painted after the whole tree, outside every clip and on whole pixels, that moves nothing when it is an absolute box; what it covers is not hovered and takes no press, and it shows only while some of its parent is in sight. And the help of a row (`help.rs`): the mark after a label that shows on its row (`help_mark`, placed by `help_label`), the panel that opens over the row from its top and is raised only at the window's bottom (`help_panel`, inside a `help_anchor`), and the small icon to click beside a text (`small_icon`). And the tick box and the tick list (`tick.rs`): the square tick box with its label (`tick_box`, like the toggle it takes no focus), the tick row (`tick_row`: a name cut at its end over a muted "how · folder" line whose folder is cut at its start, `ellipsize_start`; the whole row takes the press, Space ticks it once focused), and the tick list (`tick_list`): a line in the compact select's look that opens, above it (`TickListOpts::up`) or under it and exactly as wide, an overlay of the rows the caller builds, with thin rules (`tick_rule`) and a plain action row (`tick_action`); it stays open while rows are ticked, closes on Escape or on a press outside (which reaches nothing else) and gives the focus back to the line, reports Enter (`TickListResp::enter`), and never scrolls. A tick row, an action row and the line hold the one focus as a field does (a press, Tab); the backend sends Space as the character ' '. A status sentence under a control is `paragraph` with `TextLook::small(Tone::Warn)`, amber.
- `demos/shell-boxes`: the world preview's page shell laid out at 1400, 1200 and 1000 px and drawn as named boxes and the gallery of the page's grid rows and absolute boxes (`cargo test -p shell-boxes` writes `target/tmp/shell_<width>.png` and `target/tmp/gallery.png`).
- The world preview's window (`preview/`) and the relief demo (`relief/`) are not here: they now live in the `outpost-tools` repository (https://github.com/louisfifre/outpost-tools), which depends on this kit by git tag. `outpost-tools` pins a tag of this repository, so renaming a crate is a breaking change for it at its next pin.
- `demos/widgets`: the Design System's components as cards, one per component (`src/cards`, twenty-four: button, cover, detail-tabs, fold, help, hover-box, icon-button, list-heads, list-row, number-field, scroll-area, select, stop-button, tab-menu, tabs, text, text-field, tick-box, tick-list, tick-row, toggle, tool-button, tooltip, trend-row), each the same picture as the Design System's preview of it (`components/<Name>/preview.html`; the three tick cards follow the Apply boards until the Design System has previews of them): no caption, `SPACE_64` padding, blocks `SPACE_96` apart, a matrix being a grid of `SPACE_48` gaps whose cells are each built in their own `Ui` so one pointer can hover or hold them (`cards/mod.rs`: `Block`, `Cell`, `State`, `render`). `cargo test -p widgets --test cards` writes `target/tmp/card_<name>_<dark|light>.png` for every card in both themes (`docs/shots/card-*.png` are copies), `widgets --card NAME [--light] [--shot out.png]` opens one in a window or draws it offscreen, and `tests/behaviour.rs` drives widgets in a `Ui` (pointer, keys, characters, the input method) and checks the frame's pixels: button and toggle states, icon button looks, field focus, caret and selection, the composition's underline, the number field, the scrollbar, list rows, the tick box, the tick row (press, Space, focus, disabled, the folder cut at its start) and the tick list (its width and place, open while ticking, Escape, a press outside, Enter reported, Tab), and the amber status sentence.
- `GLOSSARY.md`: the project's words (bar, tool, view, strip, panel, stage, cut, probe, run…), confirmed with the maintainer; name things this way.
- `docs/design.md`: the design dossier (module tree, reduced flex/grid, text field, build plan, risks).
